# Efficient full-universe workflow

This changes data orchestration and model input volume, not investment thresholds or evidence requirements.

Read `agent/analytical-workflow.md` for the adopted company-model, macro/catalyst, challenge, portfolio and prospective-validation protocol. There is no token budget and no reduced analytical depth. After a completed refresh run `node app/analysis-agent.mjs run`; give selected analysts the full analytical dossier included in `research-context.mjs`, source records and specific unresolved questions. Keep numerical full-universe work in code and original evidence local, without discarding access to any required document.

1. Read `node app/scout-efficient.mjs plan`. Do not print full database tables, raw histories, full scanner responses or all company reports into the conversation. Check TradingView health and current importer ownership. Existing analyst claims are resumed before new handoffs.

   The compact plan includes saved candidate/report IDs, overdue handoffs, unresolved evidence areas and the next action. The Operations desk shows the same live backlog and opens each stock's saved research. Overdue is an update-age indicator, not authorization to take over an active owner. A late final draft must be independently re-evaluated and newly timestamped, not silently backdated or saved as if the interrupted review completed.
2. Run `node app/refresh-market.mjs` once for the authorized workflow. It refreshes the catalog weekly, snapshots by successful component receipts, and due known histories including all recorded-decision tickers. Missing scanner members remain reconciliation gaps rather than forcing every successful snapshot to download again. History reuse follows the expected completed provider session, capture finality and metadata age; provider preparation freshness is not official execution clearance. Imports checkpoint every stock and archive original responses, including failures, with persistent repair backoff and a whole-job deadline. Sunday includes unavailable catalog charts; `--retry-unavailable` is an explicit manual repair override, not a default retry loop. An unchanged scanner price never certifies a daily bar. Collector logs stay in data/market/refreshes. After collection, `prepare-data.mjs` publishes all 78 fields for every catalog stock with availability, applicability, consequences and fallback routes; no stock is dropped for a missing field.
3. After the collector finishes, run `node app/scout-efficient.mjs screen`. This evaluates the full universe with the frozen policy in code. It stores full evidence locally and returns aggregate exclusions, the five highest-ranked candidates, and at most ten eligibility/score changes. The full change list stays in the linked JSON. Resume existing claims first; screening can fill remaining capacity up to five unfinished handoffs. Existing owners are preserved and candidate duplicates are excluded. An unfinished claim does not consume every available slot.
4. Separately monitor EVERY recorded decision and export outcomes using the existing decision-agent commands. An unchanged score is not proof of unchanged news, a price trigger or investment thesis. Calendar/news/corporate-action checks remain mandatory for actual research; this optimization does not supply those sources.
5. Use one analyst batch, at most five unfinished handoffs. Give each agent candidate/context IDs and specific unresolved evidence questions. Reuse already inspected sources while their dated evidence is relevant; check for updates rather than rereading the same report. Never treat cached ownership/filings as current without checking subsequent changes. New thesis evidence goes through independent analyst and final decision agents. Preserve originals.

Read verification/wait-decision-audit-20261015.md for the starting backlog audit. That historical process audit is not new investment approval. No rule has been relaxed to force executions. Detailed evidence is loaded only for selected candidates or a changed decision, not for all 296 companies each run. This reduces model context; it does not make TradingView chart loading instantaneous or guarantee an investment opportunity.

### Versioned missing-data review and preparation

New promotions require `fieldEvidence.version = egx-field-evidence-2` as documented in `agent/field-evidence-workflow.md`. Legacy reports remain historical; a new approval requires current field-level verification. An incomplete optional field does not make an entire evidence section unreviewed; required core facts and every relied-upon field still need dated sources. No investment or execution approval follows from a collector status.

Use `node app/collect-documents.mjs` for the allowed-source URL inventory already present in saved reports. It preserves content-addressed bodies, conditional validators, response attempts and repair times. A successful download is unreviewed evidence, not proof of publication, original-document completeness or news coverage. Analysts must verify it and pursue missing issuer/official routes. `node app/prepare-data.mjs` republishes the baseline without any chart fetch. Schedules remain paused until the user explicitly resumes them.

For the initial full catalog document-route inventory, add `--universe`. This probes provider filing inventory pages as additional discovery routes; an unavailable route does not mean the issuer has no disclosures. The collector holds `data/research/evidence/library/collector.lock` exclusively. A crash leaves the owner PID and time visible: verify that process has exited before explicitly removing that one lock and resuming. Never remove an active or uncertain owner's lock. Responses already checkpointed in the index retain their next-check/repair times on restart.

### Targeted repair and retained primary evidence

- `node app/diagnose-preparation.mjs` classifies the latest unresolved history attempts without opening charts. Empty charts, wrong symbols, missing completed sessions and conflicting retained tails stay distinct. `node app/reconcile-symbols.mjs` checks exact provider identities; finding a symbol does not verify listing status or tradability. `node app/import-market.mjs --all --failed --retry-unavailable` is an explicit failed-chart repair pass, not an hourly action. No synthesized bars or inferred suspensions.
- `refresh-market.mjs` invokes `reconcile-facts.mjs --tickers=...` only for omitted scanner members. Successful component receipts prevent redoing the full daily scan; targeted reconciliation also reuses its dated receipt. Primary financial verification remains separate from provider identity checks.
- Importers persist the original chart before navigation. A forced child interruption triggers bounded restoration and identity/timeframe/type verification. A live collector retains ownership. A failed restoration stays visible for recovery; do not launch a competing collector.
- Run `python app/inspect-documents.py` after a source collection pass. It hashes raw bytes and reuses extraction only for the matching hash and inspection version. Scanned or image-backed pages remain OCR/layout review work even if a PDF header extracts as text. `discovered-routes.json` contains observed links for the next explicit collection batch; do not recursively crawl it without reviewing scope. `collect-documents.mjs --routes=<saved-route-file>` resumes that batch. `--repair` permits an explicit bounded retry of transient/oversized responses; missing routes and denied access retain their separate backoff.
- `node app/collect-exchange.mjs --from=YYYY-MM-DD --to=YYYY-MM-DD` retains the public EGX news and financial-statement feeds with page checkpoints, raw requests/responses, content versions and explicit pagination coverage. Without a date window it resumes/reuses the latest window, then collects the new interval with a two-calendar-day overlap. `--refresh` explicitly archives and restarts a window when pagination changed or older revisions require checking. Page completeness covers only the requested categories/window; it is not all-event clearance. Current-session updates require an explicit `--to` because the default ends yesterday in Cairo.
- Reviewed PDF facts require source hash, issuer identity, fiscal period, page, unit/scale, accounting basis, method and limitations through `saveDocumentReview`. They are appended to the evidence library and selected research contexts. Exchange contexts include exact tickers and unambiguous retained ISIN associations as unreviewed evidence. Conflicting or shared identities are quarantined in identityReview; unmatched announcements remain in the full index. Association does not certify identity or clear a corporate action. No document download, scanner recovery or feed completion creates a decision or trade approval.

These commands remain manual while schedules are paused. Phase 4 execution and future experiment activation remain separate.

Screen and refresh stages record actual durations and failures. Refresh timing sidecars checkpoint completed stages; model token usage is explicitly unavailable rather than guessed. This instrumentation does not prove the end-to-end latency target or implement a complete resumable orchestrator.
