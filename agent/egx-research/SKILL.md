## Each review

1. Read `research/profile.json`. Respect the user's current horizon. If unspecified, separate swing timing from medium/long-term company value. Missing capital, cash, costs or limits blocks numerical share-size proposals, not research. Never infer portfolio capital from this journal: it can be incomplete.
2. Check TradingView MCP health and save chart state. Use the active local watchlist; the open chart may be forex or unrelated. Refresh through the local tracker's `/api/refresh` using the token from `/api/state` if source freshness requires it. Wait for completion and inspect failures. Do not compete with another refresh or manipulate the chart while it runs. Restore symbol/timeframe after any direct exploration.
3. Run `node app/research-context.mjs` using Node 24+ (the launcher names the bundled runtime if Node is not on PATH). Keep the returned immutable context ID. Inspect capture times, EGX identity, native EGP/USD currency units, 900-second feed delay, gaps, adjustment policy and bar finality before forming an entry view. Read `research/session-policy.json` and each stock's `latestFinality`: same-day bars need persisted post-close capture evidence (session end + feed delay + 30-minute buffer). Unknown timing metadata requires later-date recapture. Do not independently discard all current-date bars or promote an earlier intraday capture by elapsed time alone. A tool connection alone does not establish current data. Missing raw volume must not become zero. Stale/incomplete inputs produce “Insufficient evidence” or “Watch”, never a timely execution instruction.
4. Review holdings first: actual fill ledger, open quantities, cost, realized/unrealized P/L, saved stop/target and aggregate ticker/sector exposures. Manual journal statuses do not close fills. Flag contradictory status, missing fills, stale marks and unadjusted split/dividend effects. Review exits before suggesting new exposure.
5. Build current evidence: TradingView daily/weekly structure, volume and volatility; issuer/EGX filings and corporate actions; company financials/valuation; CBE macro releases and FX/rate sensitivity; relevant credible news. Open sources rather than relying on snippets. Record publication/event dates, reporting periods, currency/scale and access timestamps. A calendar page is not proof of a company's results. Disclose inaccessible/paywalled sources and conflicting numbers.
6. Compare fundamentals, quality/value and momentum; specify catalysts, bear case and alternative explanation. Institutional papers justify research hypotheses, not proof of an EGX edge. Do not infer insider/institutional accumulation from a candle, volume spike or Pine label. Correlated indicators are not independent votes. Use the existing 0.5-ATR/2-ATR rules as labelled prototype heuristics, not bank methodology.
7. Prioritize swing trades (days to weeks) and medium-term trades (weeks to months), per the user's preference. Propose conditional positions and entry points before capital is supplied: quantify entry minus stop in the stock’s native currency per share, percentage downside, upside and reward/risk, and assign a qualitative risk assessment with reasons (liquidity, leverage, volatility, event/FX exposure). Do not present a qualitative label as a calibrated loss probability. For each candidate, state entry zone/trigger, as-of data, stop rationale/invalidation, target rationale, gross and cost-adjusted reward/risk, liquidity/holding period and what would cancel it. Costs that are unknown require explicit scenarios. No numerical fair value without an auditable model and dated inputs. Use sector-appropriate valuation: banks need capital/credit quality and ROE/PB context; real estate requires delivery/cash collection/debt context; industrials require margins, cash flow and leverage. Avoid universal PE rankings across sectors.
8. USD stocks require separately verified FX and sizing support; the existing EGP helpers and journal must not treat USD prices as EGP. Use `sizeCandidate` from `app/research.mjs` only with user-approved profile values, validated positive entry/stop, historical median daily shares and full existing portfolio exposure/risk. Apply risk, cash, concentration and volume caps, and assess sectors/correlations separately. Simultaneous candidates share cash/risk budgets: allocate sequentially or present mutually exclusive scenarios. Stop sizing is a scenario, not a guaranteed maximum loss. No discretionary default risk percentages.
9. Challenge the thesis. Existing replay is exploratory: three-then-six-stock selection, revised historical data, daily ambiguity and costs limit it. Before calling a strategy validated, require point-in-time universe/corporate actions, walk-forward or untouched test data, benchmark/total-return consistency, turnover/cost stress, liquidity capacity and marked-to-market drawdowns. Do not tune and evaluate on the same sample.
10. Save a structured report with sources, limitations and per-stock verdicts using `node app/research-save.mjs <draft-path>`. Keep original context and source dates. Tell the user which tools actually succeeded versus unavailable capabilities, which stocks remain unresearched, and what is missing for sizing. Do not label a readiness/setup report a completed market review.
